# v1.1 Design System Audit — Findings

Severity legend: **D**=Defect (broken/contradictory) · **W**=Weakness (below bar) · **O**=Opportunity (elevate)

## Confirmed before audit
- **D1 — Orphaned shadcn token set.** Second brand (orange `--primary` #FF8400, bone `--background` #F2F3F0, Geist font) coexists with the live slate+blue+Inter system. Live boards use slate+blue; orphaned set is unused but resolvable. Resolution: remove after zero-reference check (Phase 2).
- **W1 — Status colors off-brand & orphaned.** success/error/warning/info exist only in the orphaned set with values that don't match the slate+blue language. Resolution: define proper status tokens in slate+blue (Phase 2).

## 1. Visual identity
- **O1.1** — Palette and identity are cohesive and on-brief: near-monochrome cool slate (`primary-900` navy, 10-step neutral ramp) + a single blue accent (`accent-500` #2563EB), dark executive covers. This is the Linear/Stripe/Vercel register. **Keep; refine, don't replace.**
- **O1.2** — Display headings (XL/L/M) render at default tracking; large display type reads tighter and more editorial with negative letter-spacing. Opportunity to elevate premium feel. (→ Foundation v2 type scale.)
- (See D1 — orphaned shadcn brand set — under §3.)

## 2. Typography
- **W2.1** — Line-heights are **not documented per type step**. The scale shows size + weight + usage but no leading, so vertical rhythm is left to chance when components/patterns are built. (→ Foundation v2 documents lineHeight per step.)
- **W2.2** — **No long-form / prose reading treatment.** Body specimens are single lines; the site's core is content-heavy (case studies, essays, resume). There is no constrained measure or generous-leading prose style, which is exactly what a "premium publication" needs. (→ Foundation v2 prose style + `text-prose`/`measure-prose`/`leading-prose` tokens.)
- **O2.1** — Hierarchy is correctly driven by size + weight, never color. Inter (UI/display) + JetBrains Mono (labels) are well chosen. **Keep.**

## 3. Tokens
- **D1** (confirmed) — Orphaned `--`-prefixed shadcn brand set (orange `--primary`, bone `--background`, Geist fonts) coexists with the live slate+blue system. Live Foundation/Tokens boards reference only the non-prefixed semantic tokens (`$surface`, `$border`, `$surface-subtle`, `$text-*`, `$action-*`). Resolution: remove after zero-reference scan (Task 0.5 / Phase 2).
- **W1** (confirmed) — No on-brand status tokens. (→ Phase 2 adds `status-*-fg`/`-surface`.)
- **O3.1** — No prose/reading tokens (`measure-prose`, `leading-prose`, `text-prose`) to back long-form. (→ Phase 2.)
- **O3.2** — Minor naming overlap: legit non-prefixed `border`/`surface` vs. orphaned `--border`/`--card`. Removing the orphaned set eliminates the ambiguity.
- **Orphaned-token reference status:** Foundation, Tokens, Components, and Patterns boards visually render only the non-prefixed semantic layer (slate+blue, no orange/bone/Geist anywhere). Conclusion: the `--`-prefixed set is **unreferenced by rendered design**.
- **D1 RESOLUTION (Phase 2):** `set_variables` offers no per-key delete, and a full-table `replace:true` would risk corrupting the frozen v1.1 baseline (60+ tokens hand-transcribed). Chosen the safe, defect-killing path: **neutralized** all `--` tokens by re-pointing them to canonical aliases (`--primary`→`$accent-500`, `--background`→`$surface-primary`, `--font-secondary`→Inter, `--color-*`→`status-*`, etc.). The rogue orange/bone/Geist brand can no longer be expressed by any token name; the legacy set is documented deprecated on the Tokens v2 board. v1.1 verified pixel-identical to Phase 0 baseline afterward.

## 4. Components
- **W4.1 — Case Study Card buries the outcome.** Anatomy is right (category → outcome-oriented title → summary → outcome stat → CTA), but the outcome **metric is small and understated** relative to the title. For the primary discovery surface, the impact/scale number is what establishes credibility fastest and should anchor the card. (→ v2 Case Study Card promotes the outcome value to a large display weight, adds a divider, strengthens the CTA.)
- **W4.2 — No featured/standard differentiation.** All cards are uniform; there is no large "featured case study" treatment to lead the eye. (→ v2 discovery pattern + a featured card composition.)
- **O4.1 — Missing long-form components.** No Pullquote, Callout/Aside, or Table-of-Contents rail — the building blocks a premium publication needs for case-study/essay reading. (→ Phase 3 adds them.)
- **O4.2 — Missing wayfinding/credibility parts.** No Breadcrumb (for deep case-study pages) or Credibility/logo strip (fast trust on the homepage). (→ Phase 3.)
- **O4.3** — Buttons, Nav, Tag, Metric, Timeline, Footer are competent and token-driven. Refine for consistency (focus states, tracking, on-accent labels) rather than rebuild. **Mostly keep.**

## 5. Patterns
- **D5.1 — Duplicate section.** The Patterns board has **two sections both named "Page Layout Patterns"** (`EtY4W` and `a6Cf4F`). Redundant/confusing. (→ v2 board has a single, complete Page Layouts section.)
- **W5.1 — Case-study detail lacks a long-form reading body.** The detail header + metrics band are good, but there is no prose-measure reading column, Table-of-Contents rail, pullquote, or callout beneath it. The site's core job is long-form consumption; this is the biggest pattern gap. (→ Phase 4 long-form detail pattern + Phase 3 components.)
- **W5.2 — Resume leads with a boxed name card, not impact.** Executive credibility is fastest when scale/impact metrics sit at the very top. v2 resume should open with positioning + a metrics band (years, teams scaled, platform scale) before the timeline. (→ Phase 4 resume pattern.)
- **O5.1** — Hero, Writing, Contact patterns are competent and on-brand. Refine hero to surface a credibility strip; keep the rest largely as-is.

## 6. Content hierarchy
- **O6.1** — Headlines already follow the outcome-oriented rule ("Scaling Clinical Scheduling Through Optimization"). **Keep and reinforce** in v2 content guidelines.
- **W6.1** — On the homepage flow, case studies should be the unmistakable hero; v2 discovery pattern makes the featured case study + outcome metrics the dominant visual anchor above the fold.

## 7. Executive credibility
- **O7.1** — The dark covers, restraint, and slate+blue palette read as mature and executive — not startup/marketing. **Strong; keep.**
- **W7.1** — Fast-trust signals are thin: no credibility/logo strip near the hero, and resume impact metrics are not surfaced first (see W5.2). v2 addresses both.

## 8. Accessibility
- **A8.1 — `text-muted` / `text-tertiary` (`neutral-500` #64748B) on `surface-primary` (#FFFFFF):** contrast ≈ **4.76:1** → **AA pass** for normal text (≥4.5:1). No change needed.
- **A8.2 — New `text-prose` (`neutral-800` #1E293B) on white:** ≈ **13:1** → AAA. Safe for long-form body.
- **A8.3 — New status foregrounds** are dark on light surfaces (Light) / light on dark surfaces (Dark) by construction → expected AA pass; re-verify on the Tokens v2 board after Phase 2.
- **A8.4 — Button label** `text-on-accent` (#FFFFFF) on `action-primary` (#2563EB): ≈ **4.6:1** → AA pass for the 14px/600 label.

## 9. Governance
- **O9.1** — Layer separation (Foundation → Tokens → Components → Patterns → Pages) is documented on every board with a Governance section and HERE marker. **Strong discipline; carry forward.**
- **D9.1** — The orphaned token set (D1) is the one real governance breach: two answers to "what is primary." Fixing it is the headline governance win of v2.

## letterSpacing unit (confirmed in Task 1.3): **px** — negative px tracking on display (-1.5 → -0.3) renders correctly with no glyph collision. Use px values throughout.
